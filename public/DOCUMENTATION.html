1. Описание проекта

Что это за проект?

DJ GooD OFF FM — это Telegram Mini App для прослушивания онлайн-радио. Приложение работает как веб-сайт, который открывается внутри Telegram и выглядит как нативное приложение. Никаких установок из App Store или Google Play — пользователь просто открывает бота в Telegram и сразу слушает радио.

Какие задачи решает?

  • Прослушивание радио без установки отдельных приложений — пользователь просто открывает Mini App в Telegram
  • Отображение названия текущего трека — автоматически обновляется каждые 5 секунд, с очисткой DJ-метаданных (Camelot keys, Energy, BPM, URL-водяные знаки)
  • Визуальный эквалайзер — показывает частоты звука в реальном времени через Web Audio API
  • Настройка звука — 3-полосный эквалайзер (Bass/Mid/Treble) + усиление громкости до 250%
  • Подсчёт слушателей — показывает, сколько человек слушают радио прямо сейчас, через Cloudflare Worker с уникальной идентификацией по Telegram ID
  • Загрузка обложек — автоматически ищет обложки треков в Last.fm, Apple Music и AzuraCast
  • AI-DJ — автоматическая генерация голосовых вставок между треками (Ollama + Piper TTS)

Как работает (простым языком)?

ПОЛЬЗОВАТЕЛЬ открывает Telegram --> нажимает на Bot --> открывается Mini App
                                        |
                        Мини-приложение загружается с Vercel (HTTPS)
                                        |
                        Приложение подключается к аудиопотоку AzuraCast (HTTPS, CORS)
                                        |
                        Пользователь слышит музыку и видит название трека
                                        |
                        AI-DJ Pipeline на сервере генерирует голосовые вставки
                        (Ollama --> AI-DJ App --> Piper TTS --> AzuraCast Streamer)

Ключевые понятия:

  • Telegram Mini App — веб-страница, которая открывается внутри Telegram как приложение
  • AzuraCast — программа на сервере, которая вещает радио в интернет и отдаёт HTTPS-поток + API
  • Vercel API Routes — серверные функции, которые обрабатывают данные (очистка треков, обложки)
  • Cloudflare Worker (listeners) — облачная функция для подсчёта уникальных слушателей по Telegram ID
  • AI-DJ Pipeline — цепочка Ollama (LLM) + Piper TTS для генерации голосовых вставок между треками

8. Аудит безопасности

Полный аудит проекта выявил ряд критических проблем. Ниже — все находки, разделённые по приоритету.

⚠ CRITICAL — требует немедленного исправления

CRITICALSSH password auth + слабый пароль
На сервере включена SSH-авторизация по паролю с паролем vbox1. Это позволяет злоумышленнику подобрать пароль брутфорсом и получить полный доступ к серверу.
Решение: Отключить PasswordAuthentication в /etc/ssh/sshd_config, использовать только ключи. Установить fail2ban.
CRITICALНет файрвола (UFW не установлен)
Все порты сервера открыты наружу. Любой сервис, запущенный на сервере, доступен из интернета.
Решение: Установить UFW, открыть только 22 (SSH), 80 (HTTP), 443 (HTTPS). Всё остальное — закрыть.
CRITICALOllama слушает на 0.0.0.0:11434
Ollama привязан ко всем интерфейсам — любой из интернета может обращаться к LLM-модели без авторизации.
Решение: Настроить OLLAMA_HOST=127.0.0.1:11434 в переменных окружения. Перезапустить сервис.
CRITICALПустые плейлисты — AutoDJ не работает
AzuraCast выдаёт ошибку "No valid playlists detected". Автоматическое воспроизведение музыки не работает — радио молчит без ручного запуска.
Решение: Добавить треки в плейлист, включить AutoDJ, проверить назначение плейлиста на станцию.
CRITICALisAdmin отправляется с клиента (spoofing)
Флаг isAdmin формируется на клиенте и отправляется на сервер. Любой может подделать этот флаг и получить доступ к админ-функциям.
Решение: Сервер должен проверять user_id из initData (верифицированного) и сравнивать с ADMIN_USER_ID.
CRITICALLast.fm api_key=demo не работает
Используется демонстрационный API-ключ Last.fm, который не работает. Загрузка обложек через Last.fm сломана.
Решение: Получить реальный API-ключ на https://www.last.fm/api/account/create и прописать в LASTFM_API_KEY.

⚠ HIGH — требует скорого исправления

HIGHДиск заполнен на 82% (6.7 GB свободно), Swap 60%
Место на диске заканчивается. Swap используется активно — серверу не хватает RAM. Риск остановки сервисов.
Решение: Очистить логи Docker (docker system prune), проверить большие файлы, увеличить RAM или swap.
HIGHПароли в .env с правами 664
Файлы .env содержат пароли и доступны для чтения всем пользователям системы (права 664 вместо 600).
Решение: chmod 600 *.env — ограничить доступ только для владельца.
HIGHRadioMiniApp.tsx — монолит 1789 строк
Весь UI + логика + аудио + Telegram в одном файле. Трудно поддерживать, легко сломать.
Решение: Вынести логику в кастомные хуки (useAudio, useTrack, useListeners), а UI — в отдельные компоненты.
HIGHhandlePlay не обёрнут в useCallback
Функция handlePlay пересоздаётся на каждый рендер, вызывая лишние ре-рендеры дочерних компонентов.
Решение: Обернуть handlePlay в useCallback с правильными зависимостями.

MEDIUM — стоит исправить

MEDIUMMySQL Deadlock ошибки в AzuraCast логах
В логах AzuraCast периодически появляются ошибки MySQL Deadlock. Это может привести к потере данных или зависанию сервисов.
Решение: Проверить настройки MySQL, убедиться что InnoDB buffer pool достаточно большой. При необходимости перезапустить контейнер.
MEDIUMLiquidsoap latency catchup (0.2–0.44s)
Liquidsoap периодически отстаёт от реального времени на 0.2–0.44 секунды. Это может вызывать рассинхрон между названием трека и воспроизведением.
Решение: Настроить buffer_size и burst_size в конфигурации Liquidsoap. Проверить нагрузку на CPU.
MEDIUMCanvas фиксированный размер 280x60
Визуализатор использует фиксированный размер Canvas 280x60 — не адаптивен для HiDPI/Retina экранов, выглядит размыто.
Решение: Использовать devicePixelRatio для масштабирования Canvas, задавать размер через CSS.
MEDIUMMatrixBackground setInterval не останавливается
setInterval в MatrixBackground продолжает работать, когда вкладка скрыта. Тратит ресурсы CPU/GPU впустую.
Решение: Использовать Page Visibility API (document.hidden) для паузы анимации при скрытой вкладке.

LOW — можно улучшить

LOWADMIN_USER_ID захардкожен в клиенте
ID администратора хранится прямо в клиентском коде. В сочетании с отсутствием серверной проверки это создаёт риск (см. CRITICAL: isAdmin spoofing).
Решение: Переместить проверку admin-прав на сервер. Клиент не должен знать ADMIN_USER_ID.
LOWИзбыточные console.log в production
В коде много console.log, которые выводятся в консоль браузера у пользователей. Это утечка информации и загрязнение консоли.
Решение: Заменить на кастомный logger, который отключается в production. Или использовать next.config.js для удаления console.log при сборке.
